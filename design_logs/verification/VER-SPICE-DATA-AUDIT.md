Determine whether comprehensive SPICE frontend simulation data exists
to train the classifier directly on actual circuit outputs, as required
for end-to-end analog system coherence.

## Assessment

1. **Comprehensive SPICE data does NOT exist** for all DS1/DS2 records.
   Only 900 beats from 30 records (vs ~93k needed for full DS1+DS2).

2. **The rho > 0.97 claim is not supported** by cross-record data.
   The isolation test (10 beats, 1 record) showed high rho, but the
   full analog validation failed Phase 1, and cross-record pooled
   correlations are R-squared=0.004-0.607.

3. **Two test configurations disagree** on absolute voltages and even
   on the SIGN of correlation for F2.

4. **SPICE dynamic range is very small** (sigma=0.01-0.10V) compared
   to Python features (sigma=0.14-0.93). The diff pair circuits
   compress the input range significantly.

## Options for Classifier Training

### Option A: Train directly on 900 SPICE beats
- Pro: Uses actual circuit outputs as user requested
- Con: Only 900 beats (may underfit), 8 missing DS1 records, 9 missing DS2 records
- Con: Class imbalance — most beats are Normal, minority classes underrepresented

### Option B: Run more SPICE simulations
- Pro: Gets actual circuit data for missing records
- Con: Each record takes ~80-120s of simulation = ~40 min for all missing records
- Con: Need to decide which test configuration (chain vs integ) to use

### Option C: Use Python proxy calibrated against SPICE
- Pro: Full coverage of all 44 records, all beats
- Con: Python-SPICE correlation is imperfect (R-squared 0.004-0.607)
- Risk: Features with poor R-squared (F3, F4, F5) may hurt classification

### Option D: Hybrid — SPICE where available, Python proxy for missing
- Pro: Best of both worlds
- Con: Inconsistency between SPICE and proxy features in training data
