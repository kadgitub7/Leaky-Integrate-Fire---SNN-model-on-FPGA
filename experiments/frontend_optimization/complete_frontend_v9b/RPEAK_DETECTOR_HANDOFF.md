# R-Peak Detector — Design Handoff Document

## 1. Project Context

### What This Is
This is an **ultra-low-power fully-analog ECG classifier** implemented in **SKY130 130nm CMOS** at **VDD = 0.9V** in **subthreshold operation**. The system processes raw ECG signals from body electrodes, extracts 8 analog features, and classifies heartbeats using a ReRAM crossbar-based neural network.

### Role of the R-Peak Detector
The R-peak detector is the **master timing reference** for the entire frontend. Every downstream feature extraction circuit depends on the R-peak trigger to know when a QRS complex is occurring. The R-peak detector fires a pulse at the R-peak of each heartbeat, and this pulse:

1. **Precharges the delay timer** — a capacitor timer that generates post-R trigger pulses at precise delays (R+14ms, R+69ms, R+83ms, R+300ms, R+10ms) for feature capture
2. **Precharges the RR timer** — measures beat-to-beat intervals for features F1 (RR ratio) and F2 (RR asymmetry)
3. **Arms the P-wave predictor** — generates pre-next-R triggers for feature F5 (P-wave energy)
4. **Gates the peak tracker** — an optional true-peak detector that refines timing

**If the R-peak detector misses a beat or fires at the wrong time, ALL 8 features are corrupted for that beat and potentially subsequent beats (due to EWMA state corruption).** This is why near-100% detection accuracy is non-negotiable.

### The 8 Features (for reference)
| Feature | Name | What It Captures | Trigger Source |
|---------|------|-----------------|----------------|
| F1 | RR Ratio | Beat-to-beat interval ratio | R-peak precharge |
| F2 | RR Asymmetry | Interval asymmetry | R-peak precharge |
| F3 | Beat Instability L0 | ECG amplitude at R-peak, Lead 0 | R-peak + delay |
| F4 | Beat Instability L1 | ECG amplitude at R-peak, Lead 1 | R-peak + delay |
| F5 | P-wave Energy | P-wave amplitude difference | P-wave predictor |
| F6 | QRS Width | Pulse width of QRS complex | R-peak + delay |
| F7 | Slope Ratio | QRS upslope vs downslope | R-peak + delay |
| F8 | QRS Symmetry | ECG at R-peak apex | R-peak + delay |

## 2. Requirements — Hard Constraints

### Detection Performance
- **Sensitivity: >= 99.5%** across all MIT-BIH records (target: 100%)
- **Positive predictive value: >= 99.5%** (no false detections on P-waves, T-waves, noise)
- **Beat-to-beat timing jitter: <= 1ms** (features F3, F7, F8 sample on steep QRS slopes — 1ms jitter at 100mV/ms slope = 100mV capture error)
- **Detection latency: consistent** (absolute latency is calibratable; jitter is not)
- **Refractory period: 200ms** minimum to prevent double-detections

### Technology Constraints
- **Process**: SkyWater SKY130 130nm CMOS (open-source PDK)
- **Models**: BSIM4 models from `sky130_minimal.lib.spice` (tt corner)
- **Supply**: VDD = 0.9V, VSS = 0.0V
- **Operation regime**: Subthreshold (all analog MOSFETs operate below Vth)
- **Bias voltage**: vbias = 0.40V (generated by beta-multiplier bias_gen)
- **SPICE simulator**: ngspice (at `C:\Spice64\bin\ngspice_con.exe`)
- **Required .option**: `scale=1.0u method=gear reltol=0.01 gmin=1e-15`

### Component Constraints
- **MIM capacitors**: `sky130_fd_pr__cap_mim_m3_1`, C = W * L * 2e-3 pF (with scale=1.0u)
- **NFETs**: `sky130_fd_pr__nfet_01v8` (standard Vth)
- **PFETs**: `sky130_fd_pr__pfet_01v8` (standard Vth)
- **HVT PFETs**: `sky130_fd_pr__pfet_01v8_hvt` — **DO NOT USE for pseudo-resistors at 0.9V** (see Critical Finding #1)
- **No digital logic IPs** — all logic gates built from discrete MOSFETs
- **No resistors** — use MOSFETs in subthreshold as current sources instead

### ECG Signal Characteristics
- **Baseline voltage**: ~0.30V (after instrumentation amplifier, centered around vref)
- **R-peak amplitude**: 0.35V–0.50V (100–200mV above baseline)
- **QRS upslope**: 10–100 mV/ms (varies by record and morphology)
- **QRS downslope**: 5–50 mV/ms
- **QRS width**: 60–120ms
- **Heart rate range**: 40–180 bpm (RR = 333ms–1500ms)
- **P-wave amplitude**: 5–30mV
- **T-wave amplitude**: 20–80mV
- **Baseline wander**: up to 50mV slow drift

## 3. The Python Reference Model (Golden Reference)

**File**: `scratchpad/analog_detector_final.py`

This Python implementation achieves **F1 = 0.9932 across all 43 MIT-BIH records** and serves as the gold standard. The analog circuit must replicate its signal processing chain.

### Algorithm Pipeline
```
ECG → BPF(5-15Hz) → d/dt → |x| → dual envelope → noise gate → detect
```

### Stage-by-Stage Mapping

| Stage | Python | Analog Equivalent | Purpose |
|-------|--------|-------------------|---------|
| 1. Bandpass 5-15Hz | `butter(2, [5,15])` + `sosfiltfilt` | HPF (5Hz gm-C) + LPF (15Hz gm-C) | Isolate QRS frequency band |
| 2. Derivative | `np.diff()` | Capacitive differentiator | Emphasize sharp QRS slopes |
| 3. Rectification | `np.abs()` | Half-wave or full-wave rectifier | Make polarity-independent |
| 4. Fast envelope | `envelope_follower(tau=100ms)` | Leaky peak detector | Track QRS energy peaks |
| 5. Smoothing | `moving_average(30ms)` | Low-pass filter | Smooth fast envelope |
| 6. Slow average | `rc_lowpass(tau=1.5s)` | Ultra-slow OTA follower | Baseline noise estimate |
| 7. EWMA threshold | `spki/npki` adaptive | Peak tracker + weighted summer | Adaptive detection level |
| 8. Noise gate | `NOISE_RATIO * env_avg` | Comparator with offset | Reject low-SNR noise |
| 9. Refractory | 200ms minimum gap | Capacitive hold circuit | Prevent double-detection |
| 10. Peak search | `argmax(ecg[d±75ms])` | True peak detector | Locate actual R-peak apex |

### Key Parameters
```python
NOISE_RATIO = 3.0        # Noise gate: env_fast > 3.0 * env_avg
THRESHOLD_FRAC = 0.25    # Adaptive: threshold = npki + 0.25*(spki - npki)
SLOW_TAU = 1.5           # Slow average time constant (seconds)
FAST_TAU = 0.100         # Fast envelope decay (seconds)
SMOOTH_MS = 30           # Smoothing window (milliseconds)
REFRACTORY_MS = 200      # Minimum inter-detection gap
TWAVE_MS = 360           # T-wave rejection window
ALPHA = 0.125            # EWMA update rate
```

## 5. Critical Findings — What We Learned

### Finding 1: Pseudo-Resistors Do Not Work at 0.9V
**Anti-parallel HVT PFET pairs** (the standard pseudo-resistor topology) conduct only **~20 femtoamps** at VDD=0.9V. The HVT PFET threshold |Vtp_hvt| ≈ 0.6V means with Vgs=0, the device is deeply off. This creates R ≈ 10^15 ohms, making settling times of millions of seconds.

**Tested**: Both `sky130_fd_pr__pfet_01v8_hvt` and standard `sky130_fd_pr__pfet_01v8` show the same ~20fA in anti-parallel configuration at 0.9V.

**Implication**: Any topology from 1.8V literature that uses pseudo-resistors needs replacement. Use **OTA-based DC feedback** instead (proven to work — see Finding 2).

### Finding 2: OTA-Based DC Feedback Works at 0.9V
A weak OTA (tail L=20 W=0.42, ~50pA) configured as a unity-gain follower successfully holds a node at vbias = 0.40V. The virtual ground in a capacitive-feedback LNA configuration stayed within ±10mV of target.

**Test file**: `scratchpad/_tb_v4_ota_debug.spice`
**Data**: `scratchpad/_v4_debug_data.txt`

The cap-feedback LNA showed inverting gain (input 0.3→0.5V produced output 0.4→0.23V) with the OTA DC restore holding n_inv near 0.4V. However, gain was only -0.9 instead of expected -6, because the 200pF output load cap overwhelmed the OTA.

### Finding 3: 5T OTA Topology is the Workhorse
Every working analog block in this project uses the same **5-transistor OTA**:
```
XM1 cn1 in_diode tail vss NFET L=2 W=4    ; diode-connected input
XM2 out in_mirror tail vss NFET L=2 W=4    ; mirror input
XM3 cn1 cn1 vdd vdd PFET L=2 W=4           ; PMOS diode load
XM4 out cn1 vdd vdd PFET L=2 W=4           ; PMOS mirror load
XM5 tail vbias vss vss NFET L=X W=Y        ; tail current source
```

**Key behavior**: Output follows the DIODE-connected (cn1) side gate. NOT the mirror side. The OTA acts as a voltage follower from the diode input to the mirror output.

**Tail sizing controls bandwidth**:
- L=4 W=0.42 → ~400pA → gm ≈ 6nS (fast, for signal-path blocks)
- L=8 W=0.42 → ~100pA → gm ≈ 1.5nS (medium, for comparators)
- L=20 W=0.42 → ~50pA → gm ≈ 740pS (slow, for bias restore)
- L=100 W=0.42 → ~5pA → gm ≈ 70pS (ultra-slow, for EWMA averages)

### Finding 4: Comparator Offset via W-Mismatch
Systematic offset in a subthreshold diff pair:
```
Vos = n * Vt * ln(W1/W2)
```
Where n ≈ 1.3 (subthreshold ideality), Vt ≈ 26mV, so nVt ≈ 34mV.

Examples:
- W=2.5 vs W=2.0: Vos = 34 * ln(1.25) = 7.6mV
- W=4.3 vs W=4.0: Vos = 34 * ln(1.075) = 2.5mV
- W=7.0 vs W=4.0: Vos = 34 * ln(1.75) = 19mV

This is used for noise gates, tracking comparators, and peak-detect thresholds.

### Finding 5: Differentiator DC Bias Drift
The first v4 attempt's differentiator output drifted from 0.40V to 0.17V because the downstream peak detector's pass gate provided a leakage path when the comparator was in its linear region. The OTA bias-restore (50pA) couldn't overcome this leakage.

**Fix**: Use comparator offset (Finding 4) in the peak detector to ensure the comparator is fully OFF during quiescence, preventing pass-gate leakage.

### Finding 6: Python Model Validates Half-Wave at 95.9%
**File**: `scratchpad/test_analog_bpf_detector.py`

Python simulation of an analog-realizable detector (causal 1st-order filters, no zero-phase tricks):
- Full-wave rectification: 97.3% mean sensitivity
- Half-wave rectification: 95.9% mean sensitivity
- No derivative stage: 77.9% mean sensitivity (proves derivative is essential)

### Finding 7: ngspice Wrdata Format
ngspice `wrdata` outputs interleaved columns: `time1 val1 time2 val2 time3 val3 ...`

Signal N (1-indexed) is at column `2*N-1`, and its time is at column `2*N-2`. NOT the intuitive `(time, val1, val2, ...)` format.

## 6. Architecture Review — 6 Issues to Address

These issues were identified in a detailed review of the v3/v4 detector:

### Issue 1: Half-Wave Peak Hold ≠ Full-Wave/Squared
The Python model uses `np.abs()` (full-wave rectification). The analog v4 uses half-wave (leaky peak detector catches only positive derivatives). Full-wave captures both QRS upslope AND downslope energy, giving 1.4% more sensitivity.

**Options**: 
- Accept half-wave at 95.9% sensitivity
- Implement full-wave via two oppositely-poled fast_envelopes feeding the same output cap
- Implement analog squarer (Pan-Tompkins original) — requires careful topology at 0.9V

### Issue 2: Smoother Not Characterized
The 30ms smoothing stage in Python uses a moving average. The analog equivalent is a low-pass filter, but the time constant and attenuation need verification.

### Issue 3: Adaptive Threshold 60/40 Unverified
The adaptive threshold uses a weighted sum of slow average (60%) and peak level (40%). The OTA-based summer's actual weighting ratio needs measurement, not just design calculation.

### Issue 4: Noise Gate Additive Not Multiplicative
The Python model uses a multiplicative noise gate: `env_fast > NOISE_RATIO * env_avg`. The analog implementation uses an additive offset: `mwi_out > slow_avg + offset`. These are mathematically different. Need to determine if the additive approximation is sufficient.

### Issue 5: 150ms Refractory Insufficient Alone
The Python model has 200ms refractory PLUS a T-wave rejection algorithm that checks if a candidate's amplitude is less than half the previous detection. The analog refractory hold alone may not reject large T-waves.

### Issue 6: Detection Timing ≠ R-peak Timing
The detector fires when the envelope crosses the threshold, which is NOT the R-peak time. The search-back step in Python (`argmax(ecg[d±75ms])`) maps the detection back to the actual R-peak. The analog true_peak_detector serves this role.

## 8. Design Methodology — MUST FOLLOW

### Phase A: Audit Before Modifying
1. Netlist audit: trace every signal source-to-destination. Check for floating nodes, incorrect connections, conflicting drivers.
2. Electrical audit: verify DC operating points, bias currents, time constants, voltage headroom.
3. Testbench audit: verify ECG amplitude, baseline, sample rate, initial conditions.

### Phase B: Establish Quantitative Specification
Derive from ECG data: input voltage range, R-peak amplitude range, QRS slope range, beat-to-beat interval range. Set hard targets.

### Phase C: Modular Verification
**Test each subcircuit independently before integration**:
- Comparator: switching polarity, threshold, offset, delay
- Peak tracking: tracking error, speed, max trackable slew rate
- Hold and reset: reset polarity, leakage, recovery
- Peak-passed detection: trigger delay vs true peak

### Phase D: Controlled Experiments
One variable at a time. Record baseline config, state hypothesis, predict expected effect, run simulation, measure, compare, explain.

### Phase E: Synthetic → Real ECG
1. Validate with synthetic inputs (ramps, triangles, different amplitudes)
2. Then validate with real ECG records

### Phase F: Integration
Only integrate after standalone characterization is complete. Verify all trigger polarities/pulse widths/downstream timing.

### Phase G: Acceptance
Report: sensitivity, false positives, timing error mean/std/max, trigger latency, pulse width, tracking error. Use multiple records.

## 11. Known Pitfalls

1. **Never use pseudo-resistors at 0.9V** — they don't work (Finding 1)
2. **Always use `scale=1.0u`** in .option — without it, SKY130 models fail to load
3. **OTA output follows the DIODE side** — not the mirror side. Getting this wrong inverts polarity.
4. **MIM cap formula**: C_pF = W * L * 2e-3 (with scale=1.0u). Example: 100x100 → 20pF.
5. **ngspice wrdata format**: interleaved `(time, val, time, val, ...)` NOT `(time, v1, v2, ...)`
6. **Subthreshold current**: I ∝ exp(Vgs/(nVt)), n ≈ 1.3, Vt ≈ 26mV → nVt ≈ 34mV
7. **Large simulations may time out** — the full frontend with true_peak_detector exceeds 20min on some records. Consider simulation windowing (first 10s of each record).
8. **Initial conditions matter** — set all analog nodes to their expected DC value with `.ic` and use `uic` in `.tran`. Without this, circuits may take seconds to settle, consuming simulation time.
9. **Don't trust comments in SPICE files** — always recalculate equations independently (some legacy comments are wrong).

## 13. Glossary

| Term | Definition |
|------|-----------|
| **5T OTA** | 5-transistor operational transconductance amplifier (the basic building block) |
| **BPF** | Band-pass filter (HPF + LPF in series) |
| **gm-C** | Filter topology using OTA transconductance (gm) and capacitors |
| **MIM** | Metal-insulator-metal capacitor (high density, accurate) |
| **MWI** | Moving-window integrator (smooths the rectified derivative) |
| **EWMA** | Exponentially weighted moving average |
| **Pan-Tompkins** | Classic QRS detection algorithm (bandpass → derivative → squaring → MWI → adaptive threshold) |
| **Pseudo-resistor** | Anti-parallel MOSFET pair acting as very high resistance — BROKEN at 0.9V |
| **Subthreshold** | MOSFET operating below threshold voltage, exponential I-V characteristic |
| **vbias** | Bias voltage = 0.40V, generated by beta-multiplier |
| **vref** | Reference voltage ≈ 0.30V, used as ECG amplifier output baseline |
